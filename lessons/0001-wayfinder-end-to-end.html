Lesson 0001

Wayfinder End To End

One practical lesson on how to use Wayfinder and adjacent Matt Pocock-style skills to move from a foggy idea to buildable work.

The One Thing

Wayfinder is for clearing decision fog before implementation. It is not the build phase. It creates a shared map and works decision tickets until the route is clear.

Primary sources describe Wayfinder as a tool for efforts too large or foggy for one session. It uses a map on the issue tracker and resolves tickets one by one until there is nothing left to decide before building. See the Wayfinder skill source and the AI Hero Wayfinder explainer.

The Process

1. Setup
Configure tracker, labels, and domain docs. In this repo, GitHub issues mirror local .scratch/ files.
2. Destination
Name what success means. For us: a low-cost grocery flyer site for Camaqua/RS.
3. Map
Create one canonical map issue with destination, notes, decisions, fog, and out-of-scope items.
4. Frontier
Create precise decision tickets for what can be questioned now.
5. Resolve
Use grilling, research, prototype, or task work depending on the ticket type.
6. Record
Close the ticket, record the answer there, and add a one-line pointer to the map.
7. Graduate
When decisions are clear, switch to spec/build tickets.

How The Skills Fit

  • setup-matt-pocock-skills: run once per repo so the agent knows where issues, labels, and docs live.
  • wayfinder: use when the project is too foggy to spec directly.
  • grilling: use when the blocker is your intent or preference.
  • research: use when the blocker is external facts, docs, APIs, pricing, rules, or source behavior.
  • domain-modeling: use to make a shared vocabulary, usually in CONTEXT.md.
  • prototype: use when a small throwaway build will answer a UX or technical question faster than talking.
  • to-spec / to-tickets: use after Wayfinder when the route is clear enough to schedule implementation.

Your Grocery Tracker Example

We used Wayfinder correctly because the original idea had real fog: sources, Instagram/WhatsApp legality and access, flyer granularity, categories, refresh cadence, hosting cost, extraction accuracy, and UX.

The map now says: use direct supermarket website sources for Roxo and Krolow, keep WhatsApp and stories out of v1, treat flyers as the deal unit, classify by category, refresh with GitHub Actions, keep hosting static and low-cost, use AI vision/OCR during refresh only, and show flyer-first browsing.

The important shift: we are no longer asking “what is this product?” We are asking “which current flyer should a user open today?” That makes the MVP much cheaper and simpler.

How To Know Wayfinder Is Done

  • The map has a clear destination.
  • All major decision tickets are closed.
  • Remaining unknowns are implementation details, not product fog.
  • The next tickets are build tickets, not questions.

For this project, Wayfinder is effectively done for MVP planning. The next phase is implementation: scaffold site, implement collectors, implement extraction, add schedule, add debug artifacts.

Five-Minute Exercise

Open the map issue and answer these:

  1. What is the destination in one sentence?
  2. Name one thing explicitly out of scope.
  3. Name one closed decision that changed the implementation plan.
  4. What is the next build ticket?

Ask the agent to check your answers. That feedback loop is the point of the lesson.

Quick Rule

If the next useful sentence starts with “We need to decide…”, stay in Wayfinder. If it starts with “Build the…”, leave Wayfinder and implement.
